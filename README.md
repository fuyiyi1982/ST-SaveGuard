# ST-SaveGuard · 酒馆存档守卫

为 SillyTavern 设计的本地自动备份与防丢档插件。

包含两个部分，配合使用：
- **服务端插件**：在服务器后台监控聊天文件变动，每回合自动存一份本地快照，默认保留最近 5 回合。所有备份只走服务器本地磁盘，不消耗玩家网络流量。
- **前端扩展**：在酒馆右上角增加**保存状态指示灯**，支持关闭页面防漏提醒、保存失败自动重试、一键版本回退与 30 天内误删找回。

> 前端扩展只监听酒馆本身的保存请求，不会额外上传聊天内容。

---

## 核心功能

- **右上角保存状态灯**：清晰显示 `保存中…` / `已保存 ✓` / `保存失败 ✗` / `待保存…` / `生成中 · 未保存`。
- **防手滑关闭提示**：存档尚未写回服务器时关闭或刷新网页，浏览器会直接弹出拦截确认。
- **网络失败自动重试**：遇到保存失败，自动按 3秒、10秒、30秒 阶梯重试。
- **点灯即恢复**：点击状态灯即可呼出面板，随时从最近几回合快照中还原或单独下载文件。
- **误删聊天抢救**：新建聊天时不小心勾了“同时删除聊天文件”？30 天内仍可在面板底部的「已删除的聊天」中直接找回。

## 安装说明

### 完整安装（推荐 · 服主只需配置一次）

1. 打开酒馆根目录下的 `config.yaml`，确保将 `enableServerPlugins` 改为 `true`。
2. 在酒馆根目录执行安装：
   ```bash
   node plugins.js install https://github.com/fuyiyi1982/ST-SaveGuard
   ```
3. 重启酒馆。控制台打印 `[SaveGuard] v1.1.0 watching …` 即代表运行正常。

> **提示**：服务端插件启动时，会自动将前端扩展分发到酒馆全局扩展目录。**所有客户端玩家无需单独安装任何东西**，刷新页面即可直接看到状态灯。后续重启也会自动同步更新。
> **Docker 用户注意**：请务必将容器内的 `plugins` 目录挂载到宿主机，否则容器重建后插件会丢失。

---

### 仅安装前端扩展（玩家自建、无权或不想开服务端插件）

在酒馆内依次点击：**扩展** → **安装扩展** → 粘贴本仓库 Git 地址。

*注意：此模式仅具备状态灯、未保存拦截与失败重试功能；点击状态灯恢复时会提示未检测到服务端插件。*

## 备份机制与轮换规则

- **以回合为单位**：同一回合内的多次保存（AI 输出、变量写入、手动修改、重投 reroll）均覆盖同一份快照，因此“保留 5 份”指整整 5 个回合，而非 5 次写盘。
- **进行中状态标记**：玩家发完消息但 AI 尚未回复时，暂存为“回合进行中”，完整回复后自动更新。
- **防清空与断崖保护**：若单次保存导致消息暴跌 5 条以上或被彻底清空，系统会将上一份快照锁定为「保护备份」（不计入 5 回合轮换上限，每个聊天最多锁 2 份）。
- **还原自带反悔药**：执行任何恢复操作前，当前聊天内容会先生成一份保护快照，随时可以反悔切回。
- **即插即用**：插件装好后即刻生效；原有聊天会在接下来的第一次保存时生成初始快照。
- **按聊天生命周期隔离**：聊天被删除后，快照将保留 30 天；从已删除列表恢复会直接重建文件并自动切换，不影响当前正在进行的聊天。
  *(注：重命名聊天后，旧名称会在已删除列表显示 30 天，属于正常现象；群聊暂不支持找回功能)*

## 备份路径与手动救砖

快照直接保存在酒馆用户数据目录下：
```
data/<用户名>/backups/saveguard/chats/<角色名>/<聊天名>/20261008-213045-123_00042_a_ab12cd34ef.jsonl.gz
data/<用户名>/backups/saveguard/groups/<群聊ID>/…
```

**文件名格式**：`时间` _ `楼层数` _ `状态 (a:回合完成 / u:进行中 / p:保护备份)` _ `内容哈希.jsonl.gz`

**手动恢复方法**：
用 7-Zip 或命令行 `gunzip` 解压出 `.jsonl` 文件，改回原聊天文件名，放回 `data/<用户名>/chats/<角色名>/` 即可。

## 进阶配置（可选）

将插件目录下的 `config.example.json` 复制为 `config.json`，修改后重启酒馆生效：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `keep` | 5 | 每个聊天保留的历史回合数 |
| `keepProtected` | 2 | 每个聊天最多保留几份保护备份 |
| `protectDrop` | 5 | 触发断崖保护的消息减少阈值 |
| `orphanDays` | 30 | 聊天被删除后，快照保留的天数 |
| `installUi` | true | 是否自动向所有玩家分发前端扩展 |

## 局限与注意事项

1. **无法预防客户端未发出的丢件**：服务端备份的前提是“数据已成功到达服务器”。如果在数据尚未传输完毕时强行杀后台或拔网线，服务端无法凭空变出未收到的内容（请认准右上角绿灯 ✓ 再关网页）。
2. **移动端关闭拦截限制**：手机浏览器直接划掉后台时，操作系统通常不会给页面弹出关闭拦截的机会，手机端请尽量养成看状态灯的习惯。
3. **同盘备份风险**：快照与聊天存放在同一块物理硬盘上，旨在防误删、写坏、崩档与覆盖，不能替代整机灾备或异地备份。
4. **环境要求**：Node.js >= 20，SillyTavern >= 1.12（已在 1.19.0 实测验证）。
