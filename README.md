# 存档守卫 ST-SaveGuard

给 SillyTavern 用的一个仓库，两样东西：

- **服务端插件**：在服务器上盯着聊天文件，每回合在服务器本地留一份快照，每个聊天只保留最近 5 回合。复制发生在服务器自己的硬盘上，不经过玩家的网络。
- **界面扩展**：
  - 右上角的保存状态灯：`保存中…` / `已保存 ✓` / `保存失败 ✗` / `待保存…` / `生成中 · 未保存`
  - 存档没传完就关页面或刷新时，浏览器会弹出确认
  - 保存失败会自动重试（3 秒、10 秒、30 秒各一次）
  - 点状态灯打开「恢复存档」面板，从最近几回合里选一份还原或下载

界面扩展只观察酒馆自己的保存请求，不会把聊天再上传一遍。

## 安装（搭酒馆的人做一次）

1. 打开酒馆目录下的 `config.yaml`，把 `enableServerPlugins` 改成 `true`。
2. 在酒馆目录下运行：

   ```
   node plugins.js install https://github.com/fuyiyi1982/ST-SaveGuard
   ```

3. 重启酒馆。控制台出现 `[SaveGuard] v1.0.0 watching …` 就是装好了。

插件启动时会把界面扩展放进酒馆的全局扩展目录，所以**这台酒馆上的所有玩家不用再装任何东西**，刷新页面就能看到状态灯。之后每次重启酒馆，插件会自动更新（`enableServerPluginsAutoUpdate` 默认开启）。

Docker 部署需要把容器里的 `plugins` 目录挂载出来，否则重建容器后插件会消失。

## 只装界面扩展（玩家自己跑酒馆、不想开服务端插件）

酒馆里：扩展 → 安装扩展 → 填这个仓库的 Git 地址。

这样只有状态灯、关闭提醒和失败重试；「恢复存档」面板会提示服务器没有装插件。

## 备份规则

- 一回合一份：同一回合里的多次保存（AI 回复、变量更新、编辑、重roll）会覆盖同一份，所以 5 份就是 5 回合，而不是 5 次保存。
- 玩家刚发出消息、AI 还没回的状态算「回合进行中」，下一次保存会把它换掉。
- 一次保存里消息少了 5 条以上，或者聊天文件被清空时，之前那份会被标成「保护备份」，不参与 5 份轮换，每个聊天最多留 2 份。
- 还原之前，当前内容会先留成保护备份，所以还原本身可以反悔。
- 插件装上之后才开始备份；已有的聊天在下一次保存时得到第一份。
- 聊天被删除 30 天后，它的快照才会被清理。

## 备份放在哪，怎么手动恢复

```
data/<用户名>/backups/saveguard/chats/<角色文件夹>/<聊天名>/20261008-213045-123_00042_a_ab12cd34ef.jsonl.gz
data/<用户名>/backups/saveguard/groups/<群聊ID>/…
```

文件名依次是：时间、消息楼层数、状态（`a` 回合完成 / `u` 回合进行中 / `p` 保护备份）、内容指纹。

手动恢复：用 7-Zip 或 `gunzip` 解压出 `.jsonl`，改成原来的聊天文件名，放回 `data/<用户名>/chats/<角色文件夹>/`。

## 配置（可选）

把 `config.example.json` 复制成 `config.json` 再改，重启生效：

| 项 | 默认 | 含义 |
|---|---|---|
| `keep` | 5 | 每个聊天保留几回合 |
| `keepProtected` | 2 | 每个聊天最多几份保护备份 |
| `protectDrop` | 5 | 一次少掉多少条消息算"突然变短" |
| `orphanDays` | 30 | 已删除聊天的快照保留天数 |
| `installUi` | true | 是否自动把界面扩展分发给所有玩家 |

## 局限

- 服务器备份的是**已经传到服务器的内容**。玩家在上传完成之前关掉页面，那一回合从没到过服务器，任何服务端备份都救不回来——这部分靠状态灯和关闭提醒来防。
- 手机浏览器直接划掉后台时，系统通常不给页面弹确认的机会，关闭提醒在手机上不可靠，要看状态灯是 ✓ 再关。
- 快照和聊天在同一块硬盘上，防的是聊天被覆盖、写坏、误删，不防硬盘本身损坏。
- 需要 SillyTavern 1.12 以上、Node 20 以上。在 1.19.0 上实测通过。
